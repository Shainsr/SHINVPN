# گزارش بررسی SHIN VPN

## اصلاحات انجام‌شده

1. فایل بزرگ `lib/main.dart` به بخش‌های منطقی در `lib/src/` تقسیم شد؛ `main.dart` اکنون نقطهٔ ورود و محل import/partها است.
2. مقدار پیش‌فرض نسخه از `1.00.5` به `1.00.6` هماهنگ شد.
3. Drawable مورد استفادهٔ اعلان‌ها با نام `ic_notification_vpn.xml` اضافه شد.
4. تست تونل دیگر HTTPS را به HTTP تبدیل نمی‌کند. دو درخواست با یک `HttpClient` اجرا می‌شوند تا امکان استفادهٔ مجدد از اتصال وجود داشته باشد.
5. اعتبارسنجی گواهی TLS هنگام دریافت Subscription دوباره به حالت پیش‌فرض امن برگشت؛ callback پذیرش همهٔ گواهی‌ها حذف شد.
6. نسخه‌های Gradle، Android Gradle Plugin و Kotlin در فایل‌های پروژه با نسخه‌های استفاده‌شده در CI هماهنگ شدند.
7. Workflow برای Pull Request و branch به کلید موقت CI مجهز شد؛ tagهای انتشار همچنان باید با keystore ثابت و Secrets امضا شوند.

## مواردی که باید در دستگاه یا CI واقعی تست شوند

- ساخت کامل APK با Flutter `3.29.3` و JDK 17؛ در محیط بررسی، Flutter و Dart نصب نبودند، بنابراین build و `flutter analyze` اجرا نشد.
- اتصال و قطع VPN، به‌خصوص از طریق Quick Settings، ویجت و اعلان.
- اجرای خودکار پس از راه‌اندازی مجدد دستگاه.
- وارد کردن VLESS، VMess، Trojan، Shadowsocks و لینک اشتراک.
- رفتار Ping در حالت متصل و غیرمتصل و مقایسهٔ نتیجهٔ درخواست اول و دوم.
- دریافت و نصب به‌روزرسانی از GitHub Release.

## یافته‌های باقی‌مانده / محدودیت‌ها

- تست همهٔ سرورها با حداکثر ۸ worker موازی اجرا می‌شود؛ این محدودیت فعلی است و به‌تنهایی باگ محسوب نمی‌شود.
- هنگام اتصال VPN، تست گروهی فقط سرور فعال را می‌سنجد؛ این رفتار در کد فعلی عمدی/محدودشده است.
- تست تونل با یک `HttpClient` امکان reuse اتصال را فراهم می‌کند، اما تضمین نمی‌کند سرور مقصد یا واسط شبکه اتصال را نگه دارد؛ برای اثبات Keep-Alive باید لاگ شبکه یا endpoint کنترل‌شده استفاده شود.
- `fetchSubscription` اکنون گواهی TLS را بررسی می‌کند. Subscriptionهایی با گواهی نامعتبر یا self-signed ممکن است دیگر دریافت نشوند؛ این رفتار از نظر امنیتی صحیح‌تر است.
- فایل `pubspec.lock` در ورودی وجود نداشت. برای اپلیکیشن بهتر است پس از اجرای `flutter pub get` نسخهٔ resolve‌شدهٔ وابستگی‌ها commit شود تا buildهای آینده قابل تکرار باشند.
- کد صفحهٔ اصلی هنوز یک فایل نسبتاً بزرگ (`main_shell.dart`) است؛ این مرحله فقط جداسازی امن بخش‌های سطح بالا بود و بازنویسی معماری State/UI انجام نشده است.

## فایل‌هایی که حذف نشدند

فایل‌های Android resource، manifestهای debug/profile، Gradle wrapper، فونت‌ها و منابع ویجت نگه داشته شدند؛ این‌ها فایل زائد نیستند و حذف آن‌ها می‌تواند build یا قابلیت‌های برنامه را خراب کند. هیچ build cache یا خروجی APK در ZIP ورودی وجود نداشت.
