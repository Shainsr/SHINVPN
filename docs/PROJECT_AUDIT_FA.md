# گزارش فنی و تغییرات SHIN VPN 1.1.0

## تغییرات این بسته

1. کد بزرگ اولیه به چند بخش سطح‌بالا در `lib/src/` تفکیک شده است؛ `lib/main.dart` نقطه ورود و تعریف `part`ها است.
2. نسخه برنامه به `1.1.0+49` ارتقا یافته و مقدار پیش‌فرض نسخه Dart با آن هماهنگ شده است.
3. منبع Drawable اعلان با نام `ic_notification_vpn.xml` اضافه شده است.
4. دریافت Subscription دیگر گواهی TLS نامعتبر را به‌صورت پیش‌فرض قبول نمی‌کند.
5. تست تونل، scheme تنظیم‌شده را حفظ می‌کند و HTTPS را به HTTP تبدیل نمی‌کند.
6. تست Keep-Alive با یک `HttpClient`، حداکثر یک اتصال هم‌زمان به میزبان و دو درخواست ترتیبی انجام می‌شود. اگر سرور اتصال را بعد از درخواست اول ببندد، نمونه دوم به‌عنوان اتصال reuse‌شده گزارش نمی‌شود.
7. تست گروهی سرورها از concurrency تطبیقی دسته‌ای استفاده می‌کند: از ۴ worker شروع می‌کند، در صورت موفقیت پایدار تا ۸ افزایش می‌دهد و در صورت نرخ خطای بالا تا ۲ کاهش می‌دهد. این تطبیق بر اساس نرخ موفقیت شبکه است، نه سنجش مستقیم CPU/RAM.
8. سیاست انتخاب سرور Manual شده است: پایش سلامت فقط افت کیفیت را تشخیص می‌دهد و سرور جایگزین را پیشنهاد می‌کند؛ تغییر سرور و اتصال مجدد فقط پس از تأیید کاربر انجام می‌شود.
9. تنظیم پایش سلامت با کلید جدید ذخیره می‌شود و مقدار قدیمی `autoFailover` فقط برای مهاجرت تنظیمات قبلی خوانده می‌شود.
10. Gradle Wrapper و نسخه‌های پلاگین Android در پیکربندی پروژه با نسخه‌های استفاده‌شده در CI هماهنگ شده‌اند.
11. Workflow ساخت APK برای branch/PR از کلید موقت و برای tag انتشار از Secrets امضای پایدار استفاده می‌کند.

## قابلیت‌هایی که از قبل در سورس وجود داشتند و حفظ شدند

- وارد کردن کانفیگ‌ها و لینک‌های VLESS، VMess، Trojan، Shadowsocks و SOCKS
- دریافت و مدیریت Subscription
- لیست سرورها، گروه‌بندی و فیلتر کشور
- Split Tunneling / فهرست برنامه‌های عبوری
- نمایش وضعیت و ترافیک اتصال
- تم روشن/تاریک، فونت Vazirmatn، ویجت و Quick Settings
- تایمر قطع اتصال و بررسی نسخه جدید

## مواردی که عمداً ادعای تکمیل آن‌ها نمی‌شود

- محاسبه کامل Jitter و Packet Loss برای هر سرور و امتیاز کیفیت چندمعیاره هنوز پیاده‌سازی نشده است؛ مرتب‌سازی موجود عمدتاً بر اساس Ping است.
- Adaptive scheduler فعلی از نرخ موفقیت تست‌ها برای تنظیم تعداد worker استفاده می‌کند؛ سنجش مستقیم حافظه آزاد و بار CPU در این نسخه انجام نمی‌شود.
- Keep-Alive وابسته به پشتیبانی endpoint و مسیر شبکه از اتصال پایدار است؛ برای تأیید قطعی reuse باید با endpoint کنترل‌شده و ابزار تحلیل شبکه آزمایش شود.
- Split tunneling و reconnect به رفتار کتابخانه `flutter_v2ray_client` و نسخه Android وابسته‌اند و باید روی دستگاه واقعی آزموده شوند.

## تست‌هایی که باید در CI یا دستگاه واقعی اجرا شوند

```bash
flutter pub get
flutter analyze
flutter test
flutter build apk --release --split-per-abi
```

سناریوهای دستی ضروری:

- اتصال/قطع VPN از صفحه اصلی، Quick Settings، ویجت و اعلان
- تست Ping با ۱، ۵۰ و ۲۰۰ سرور
- اجرای Ping هنگام اتصال (فقط سرور فعال)
- خاموش/روشن کردن Wi-Fi و جابه‌جایی Wi-Fi به دیتای موبایل
- تست بازیابی اتصال بدون تعویض خودکار سرور
- رد کردن و تأیید پیشنهاد سرور جایگزین
- وارد کردن کانفیگ و Subscription با TLS معتبر و نامعتبر
- اجرای طولانی‌مدت و بررسی مصرف RAM/CPU و باتری

## محدودیت اعتبارسنجی این تحویل

در محیط ساخت این بسته Flutter و Dart نصب نبودند؛ بنابراین `flutter analyze`, `flutter test` و ساخت APK اجرا نشده‌اند. این بسته از نظر فایل‌ها، ساختار ZIP و بررسی ایستای تغییرات آماده است، اما تا اجرای CI سبز و تست روی گوشی، نباید آن را Build تأییدشده یا انتشار نهایی تلقی کرد.

## فایل‌های نگه‌داشته‌شده

منابع Android، Manifestها، Gradle Wrapper، فونت‌ها، کد Kotlin، منابع ویجت و Quick Settings حذف نشده‌اند؛ این‌ها بخشی از برنامه‌اند و فایل اضافی محسوب نمی‌شوند. فایل‌های build cache و APK خروجی نیز در ZIP ورودی وجود نداشتند.
